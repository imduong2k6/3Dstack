# Solved problems

One note per problem the pipeline has solved. Research reads this folder first and only goes online when no note fits (`reference-research`, `workflow-research`). Write a note the same day the fix works.

This folder ships with the repo, so it holds no reference photos, client names or paths from one machine. Notes that need those go in the private folder, `brief.yaml › knowledge_local` (default: `knowledge/` in the work root, outside git), in the same format.

## Format (`knowledge/<short-problem-name>.md`)

```markdown
# <The problem in one line>

**Seen on:** <project, stage, date> · **Modes:** blockout | camera_match | full_cg | all · **Routes:** blender | unreal | all

**Symptom:** what the review or the user saw.
**Cause:** why it happened.
**Fix:** what worked, as steps or a rule, with the skill or script it now lives in.
**Test:** the check that catches it now (a script, a stats field, a supervisor check), or "none yet".
```
